# 发布策略（Release Strategies）

> 领域知识文档：业界通用的软件/模型发布策略谱系，**不描述本工程的实现**——本工程当前落地了其中两种形态（服务级 canary + 环境隔离，见 [deployment.md](deployment.md)），实现状态在各节末尾标注。最后更新：2026-09-05

## 1. 环境模型

环境（environment）是同一套软件为不同目的部署的实例，关键是**目的**不同：

| 环境 | 目的 | 特征 |
|------|------|------|
| 测试环境（test） | 开发验证：新功能先在自己能控制的地方跑 | 流量自造，挂了不心疼，版本可超前生产 |
| 预发环境（staging，可选） | 上线前最后验证 | 尽量对齐生产配置，可接少量灰度流量 |
| 生产环境（prod） | 对外服务：真实用户、真实流量 | 挂了就是事故，版本必须稳 |

灰度（canary）不是第四种环境，而是**发布过程中生产环境的临时形态**：生产入口背后同时挂新旧两个版本，新版本只接一小部分流量，发布收敛后即消失。

## 2. 发布策略谱系

五种基本策略，从重到轻：

| 策略 | 机制 | 爆炸半径 | 回滚速度 | 成本 | 适用 |
|------|------|---------|---------|------|------|
| 停服发布（big-bang） | 停机 → 换版本 → 开机 | 100%（窗口内全停） | 慢（再次停服） | 最低 | 无 SLA 的内部系统 |
| 滚动发布（rolling） | 逐个实例替换，LB 摘流 | 单实例 | 分钟级（LB 切回） | 低 | 通用默认选择（K8s rolling update） |
| 蓝绿发布（blue-green） | 两套完整环境，流量整体切换 | 100%（切换瞬间） | 秒级（DNS/LB 切回） | 双倍资源 | 变更风险高、要求秒级回滚 |
| 金丝雀发布（canary） | 一套环境内新旧并存，按比例逐步放量 | 可控（比例 %） | 分钟级（权重归零） | 中 | 想小范围验证再全量 |
| 特性开关（feature flag） | 代码级开关，运行时切换 | 用户级（按开关） | 秒级（关开关） | 开关治理成本 | 频繁小变更、需要精细控制 |

选择的本质是**爆炸半径 × 回滚速度 × 成本**的取舍。蓝绿与 canary 常被混淆：蓝绿是**两套环境、整体切换**；canary 是**一套环境内新旧并存、逐步放量**。

> 本工程实现状态：已落地服务级 canary（nginx 权重/header 分流，deployment.md 场景一）与测试/生产环境隔离（场景二）；停服/蓝绿/feature flag 未内置，按部署需要自行采用。

## 3. 分流机制

canary 的分流维度（入口层，如 nginx / ALB）：

- **权重**：随机分流，适合无差别放量
- **header 染色**：`X-Canary: 1` 强制走灰度，供测试固定验证
- **sticky**：同一调用方始终同版本，避免新旧行为交替出现
- **按用户特征**：用户 id / 地域等分桶——这是 A/B 实验的分流方式

**canary 与 A/B 不是一回事**：

| | canary | A/B |
|---|---|---|
| 分流依据 | 流量比例 | 用户特征 |
| 目标 | 发布（降低新版本风险） | 实验（对比两版本效果） |
| 结论 | 是否全量 / 回滚 | 哪个版本更好 |

## 4. 观测与回滚

- **观测**：错误率、延迟分布、业务指标在新旧两侧的对比；新版本冷启动用就绪探针挡流量（`/health/ready` 未就绪不接流）
- **回滚**：canary 权重归零 / LB 切回；蓝绿切回入口；feature flag 关开关
- 原则：**回滚比升级更重要**——升级失败的假设是 100%，回滚路径要在发布前就位

## 5. 与模型版本管理的关系

发布策略解决「流量怎么切」，模型版本管理解决「版本怎么命名与路由」——两者正交：

- **版本语义**：`name@version`（Docker tag、MLflow model registry、Triton model version 同模式），default 指针指向稳定版
- **发布的是指针不是权重**：模型文件按版本留存，发布 = 改默认指针，回滚 = 指针改回
- **两级发布**：服务级（deployment.md 的 nginx 灰度——新旧 web 两套代码/权重）与模型级（同一服务内按请求路由模型版本）

> 本工程实现状态：服务级发布已落地（deployment.md）；模型级版本路由（name@version + 灰度分流）**未实现**——本模板当前以服务级发布为限，注册表的热更新与版本路由属于后续演进方向。
